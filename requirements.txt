# --- Intel CPU / iGPU / NPU ----------------------------------------------
# Replaces plain onnxruntime in the same environment:
#   pip uninstall -y onnxruntime
#   pip install onnxruntime-openvino==1.24.1 "openvino==2025.4.1"
# The openvino version must match the ABI onnxruntime-openvino was built
# against. 2026.3.1 loads but the provider fails with Windows error 127
# (missing procedure) and ONNX Runtime silently falls back to CPU.
# onnxruntime-openvino==1.24.1
# openvino==2025.4.1
#
# onnxruntime-openvino does not bundle the OpenVINO DLLs; bench/backends.py
# calls openvino.utils.add_openvino_libs_to_path() before creating a session.
# Then: --backend openvino --ov-device CPU | GPU | NPU

# --- NVIDIA ---------------------------------------------------------------
# MX150 is Pascal (sm_61). If CUDAExecutionProvider does not appear in
# `python -m bench.env_fingerprint`, stay on CPU and record that.
#   pip uninstall -y onnxruntime && pip install onnxruntime-gpu
# onnxruntime-gpu bundles neither the CUDA runtime nor cuDNN, and CUDA 13 has
# dropped Pascal, so the runtime must be 12.x and must match the major the
# wheel was built against.
#
# --- Any DX12 GPU ---------------------------------------------------------
# Reaches the MX150 with no CUDA and no cuDNN; the driver is the whole
# dependency. Windows only. backends.py disables the memory-pattern planner
# and forces sequential execution for this provider, as DirectML requires.
#   pip uninstall -y onnxruntime && pip install onnxruntime-directml
#   --backend dml
#
# These four flavours all install the same `onnxruntime` package and cannot
# share an environment. One venv each; see handoff/setup-550xbe.md.
