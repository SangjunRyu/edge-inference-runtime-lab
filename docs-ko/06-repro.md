# 재현 프로그램

원문: [`repro/README.md`](../repro/README.md)

이 프로젝트를 만들며 나온 결함은 전부 **실행 가능한 프로그램**으로 남아 있다.
문단이 아니다. 각각 `--mode broken`과 `--mode fixed`를 받고, **그 모드가 예측한 대로
동작하면 종료 코드 0**이다.

```
python repro/run_all.py                  # 여기서 돌릴 수 있는 전부
python repro/run_all.py --skip-openvino  # 이식 가능한 부분집합
python repro/run_all.py --device NPU     # OpenVINO 쪽을 NPU 에서
```

## 결과가 둘이 아니라 셋이다

| 상태 | 뜻 |
|---|---|
| `ok` | broken 이 결함을 재현했고 fixed 는 아니다 |
| `NOT REPRO` | broken 모드가 깨끗하게 나왔다. 여기서 그 조건이 더는 발동하지 않는다는 뜻이지 **코드가 안전하다는 뜻이 아니고**, 수정을 걷어낼 이유도 아니다 |
| `REGRESSION` | fixed 경로가 실패했다. 이게 조치할 항목이다 |

현재 12개 중 10개가 `ok`, 2개가 `NOT REPRO`다. 표가 그렇게 말하지 통과로 반올림하지
않는다.

## `stats/`가 사실 더 중요하다

실제 하드웨어에서는 답을 대조할 게 없다. 계측기가 1.47배라 하고 진실이 1.28배여도
기계는 아무 말 안 한다. 그래서 **기계를 시뮬레이션**하고 정답을 구성으로 알고 있게
했다.

`02_order_bias`가 특히 그렇다. 실제 기계에서 편향은 **없었고**(1.274 대 1.289)
그래서 실험이 "편향 없음"과 "민감도 없음"을 구분하지 못했다. 여기선 편향을 손으로
넣는다.

```
A 고정 순서:  진실 1.280 → 측정 1.470 (편향 +14.8%, CV 1.7%)
교대 순서:    진실 1.280 → 측정 1.283 (편향 +0.3%)
```

**CV 1.7%짜리 틀린 답이다. 정밀해 보이는 오답.** 이게 없으면 쌍 안의 순서 교대는
그냥 의식이었다.

## 재현되지 않는 둘을 표에 적어둔 이유

`01`은 정의되지 않은 동작이라 재현이 조용해질 수 있다. 그래서 `--mode probe`를
넣었다. 런타임에 넘긴 디스크립터를 프로그램이 여전히 소유한 채 변형하고 콜백이 어느
값을 받는지 본다. 미정의 동작이 전혀 없어서 매번 같은 답을 낸다.

```
변형 전에 설정한 인자, 콜백이 받은 값: 0
변형 후에 설정한 인자, 콜백이 받은 값: 1
→ 런타임은 완료 시점에 디스크립터를 읽는다.
```

교착을 한 줄 수정으로 바꾼 진단이 이것이고, 재현이 조용해진 지금도 수정을 정당화하는
건 이쪽이다.

`03`은 여섯 구성({CPU, NPU} × {수집기 스레드, 콜백 내부} × {4, 16 요청})에서 전부
깨끗하게 읽혔다. `-8`은 분명히 관측됐으니 조건이 저 여섯보다 좁거나, 당시 함께 있던
dangling 디스크립터가 남긴 상태에 의존했을 것이다. 후자는 미검증이고 정직한 첫
추측이다. `wait`는 어느 쪽이든 남긴다. **문서화되지 않은 유예에 기대는 코드는 남길
코드가 아니다.**

## 06·07·08은 같은 모양의 실패다

W5-2에서 연달아 나온 셋인데 전부 같은 실수의 변형이다. **유도한 생명주기가 아닌 다른
양에 용량 논증을 적용한 것이다.**

- `06`은 실재하는 상한을 잘못 쟀다.
- `07`은 실재하는 상한을 그것이 덮지 않는 양에 대해 단언했다.
- `08`은 같은 실수로 자료구조 크기를 정했고, 이번엔 숫자가 틀린 게 아니라 **멈췄다.**

`09`는 계열이 다르다. DX-RT 윈도우 어댑터가 `CreateFile` 결과를 보지 않는데, 검사가
`#if 0` 안에 있기 때문이다. 뻔한 절반은 검사가 빠졌다는 것이고, 프로그램을 쓸 만하게
만드는 절반은 **켜도 고쳐지지 않는다**는 것이다. 감춰진 코드는 출력하고 `return`하는데
생성자에서 반환해도 객체는 만들어진다. `--mode probe`가 그걸 보여준다.

`08`은 단일 스레드에 결정적이라 어느 기계에서나 똑같이 재현된다. 그리고 drain 에
예산을 둬서 멈춤을 **보고한다.** 멈추는 테스트는 테스트가 아니다.

`06` 자체도 한 번 고쳐야 했다. 처음엔 버퍼 8개에 스레드 4개라 아무도 대기하지 않았고
`NOT REPRODUCED`가 떴다. 결함에는 경합이 필요하고, 그 사실이 이제 누군가의 기억이
아니라 프로그램 헤더에 있다.
